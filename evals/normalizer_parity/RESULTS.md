## Interpretation

The gap is real-prose vocabulary, not the two fixes in this task. RuleNormalizer is tuned for the synthetic Helix policy domain; on this natural-prose set it returns `object=None` (and therefore `polarity=None`) whenever the claim's verb falls outside its small canonical enum — `seeded`, `validated`, `restarted`, `forbidden`, `exposed`, `automatic` — which is most of the divergences below. The LLM abstracts those to canonical verbs (`allowed`/`required`/`enforced`) and resolves `must never`→`must_not`; RuleNormalizer's modal set has no `never`/`forbidden` negator, so it also flips a chunk of `modality`. **The coref + inline-code fixes shipped in this task barely move THIS number** — by design: this contradiction dataset has almost no bare-pronoun subjects or backtick spans. Those fixes target document-INGESTION prose (extract.py → remember()), which this set doesn't exercise; they are unit-tested separately.

**Decision input:** parity is far below the 85% swap threshold, so the LLM normalizer stays the default. Closing this gap would mean expanding RuleNormalizer's object/modal vocabulary + abstraction rules (a separate, calibration-sensitive effort — out of scope here, which was measure-only).

`polarity` is the derived stance (`structural._stance`): modality sign × object-polarity sign — the field the judge's polarity gate actually keys on. `subject` parity uses containment / ≥50% token-Jaccard, not exact string equality (two extractors phrase the same noun differently).
