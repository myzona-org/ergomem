Ergo  unified engine — architecture v4 & data flow (single-tenant)

One product, one engine, one container. The two halves are merged: the contradiction firewall (precision P=0.957 on the labeled prose eval) and the retrieval verbs (recall, why, with reason-history chains) live in the SAME SQLite + sqlite-vec store. Seven core verbs, five data-flow lanes, one audit trail.
Single-tenant: ERGO_API_TOKEN gates every route (a loopback-only bind still runs open if unset; a non-loopback bind refuses to start unless ERGO_INSECURE_NO_AUTH=1); a bounded ThreadingHTTPServer serves concurrent requests against ONE SQLite file that stays single-writer via BEGIN IMMEDIATE + SQLITE_BUSY retry. 0 false hard-blocks.
Bounded threading, single store
The server is a ThreadingHTTPServer capped by a per-instance BoundedSemaphore(ERGO_HTTP_MAX_WORKERS, default 8), so a slow guarded write can't head-of-line-block another read. The store opens check_same_thread=False and guards every method with its OWN RLock while BEGIN IMMEDIATE + SQLITE_BUSY retry stays the per-database serializer.

Five flow lanes

1. POST /remember  guarded  ·  + /learn
The write you want contradiction-checked (decisions, constraints). Normalize → structural compare → NLI residual (overlap-gated) → judge tier → write-guard. Returns 200 Stored or 409 Conflict. /learn runs the SAME firewall but folds a required source into the reason. Every flag goes to conflict_events.
2. POST /ingest  fact fast-path
Bulk document ingest. Word-safe chunker (no mid-word slices) → embed each chunk → remember_fact() skips normalize+judge per the README rule "fact = upsert freely". a bulk batch of reference docs ingests in seconds
3. POST /supersede  change of mind  ·  /retract wrong-at-birth
Look up old claim by composite-FK (org_id, project, id) → normalize+embed the new one outside the lock → judge against OTHER actives (the to-be-superseded is excluded) → in one txn: UPDATE old to status='superseded', INSERT new with supersedes pointer + vec row. The chain is what powers /why's history. /retract instead flips a wrong-at-birth claim to retracted — no gate, no new row.
4. GET /recall  hybrid search
Embed query with the same baked bge-small → vec_claims MATCH k = limit × 8 (cosine) → JOIN claims with status='active' (superseded rows are structurally excluded; no vec deletes needed) → blend 0.7 × vec_sim + 0.3 × word_overlap → sort and return top N.
5. GET /why  reasoned belief
recall(reasoned_only=True) so a reason-less fact can never win a "why" query → take the top reasoned hit → walk the supersede chain backwards from its id → return {claim, reason, score, history: [...]} with each historical entry's revision reason. The whole point of Ergo, in one endpoint.

What lives where

Five tables, one store
claims (the truth — statement, reason, norm, status, supersedes, claim_seq) · vec_claims (1:1 with claims, sqlite-vec virtual table, cosine KNN) · writes & conflict_events (full audit) · projects (org/project registry). Backup is one VACUUM INTO away.
Why no vec-row deletes on supersede
The supersede flow inserts a NEW vec_claims row and UPDATEs the old claims.status to superseded. /recall joins on status='active' so superseded vectors are structurally excluded from results — no expensive index deletes, history stays walkable.
Write-guard (race-safe SQLite)
Preflight read snapshot is closed BEFORE judge runs. Commit phase is BEGIN IMMEDIATE + preflight_seq recheck → retry on race. SQLITE_BUSY bounded backoff with jitter, never silent inserts on a stale snapshot.

The bet

normalize → structural → NLI
NLI alone is roughly lexical (P ≈ 0.58). The MVP bet was always that normalizing first, then using NLI only on the fuzzy residual with an overlap gate, would beat both pieces alone. Labeled prose eval: P=0.957, R=0.733, F1=0.830, 0 false hard-blocks.
Image: NLI + embedder + sqlite-vec baked, instruct LLM remote
ergo:merge bakes the embedder (bge-small, 130 MB) and NLI (deberta-v3 quant, 190 MB) into one Python 3.12 slim image and loads sqlite-vec at boot. Instruct LLM is HTTPS to LiteLLM/Anthropic; air-gap fallback is ERGO_LLM_PROVIDER=ollama — same image, different env. Boot test blocks socket.getaddrinfo and reloads everything offline; build fails on any silent fetch.
Owner-in-the-binary (anti-zombie)
/diagnose surfaces owner_name, owner_contact, backup_path, last_backup_at, last_write_at, kill_review_date — never buried in a README. Three empty-store states (UNINITIALIZED / EMPTY_PROJECT / NO_MATCH) so "no answer" can never be ambiguous.
